Archives

An archive stores the solutions found so far, and decides which of them to keep.

Interface

QualityDiversity.AbstractArchive — Type
AbstractArchive{G,F,D,P}

Supertype of archives, which store the best solution found for each region of descriptor space. The type parameters are the genotype G, the fitness F, the descriptor D and the phenotype P, so that code downstream of an archive is concretely typed. P is Nothing for an archive that stores no phenotype; see Evaluation. An archive with a phenotype type other than Nothing stores the phenotype of every solution it takes and throws for an evaluation without one.

Required methods

  • add!(archive, x, ev) → AddResult
  • cell_index(archive, d)
  • sample_elites(rng, archive, n)
  • elites(archive)
  • capacity(archive)
  • Base.length(archive): the number of occupied cells

Optional methods

  • add_batch!(archive, xs, evs)
  • Base.empty!(archive)

QualityDiversity.AddStatus — Type
AddStatus

Outcome of inserting a solution into an archive.

  • Rejected: the archive left unchanged.
  • Improved: the solution replaced a worse occupant of its cell.
  • NewCell: the solution filled a cell that was empty.

QualityDiversity.AddResult — Type
AddResult{F}(status, improvement)

Result of add!.

improvement is the fitness gain over the previous occupant of the cell, or over the archive's threshold for a cell that was empty. It is zero or negative for a rejected solution. Emitters that rank candidates by improvement, such as CMA-ME, read this field.

QualityDiversity.add_batch! — Function
add_batch!(archive::AbstractArchive, xs, evs) -> Vector{<:AddResult}

Insert every solution in xs with its evaluation from evs, returning one AddResult per solution in order. Optional: an archive specializes it when a batch can be inserted faster than one solution at a time.

The default calls add! on each solution in order. An archive may instead compute every result against its state before the batch, so that a result does not depend on the other solutions in the batch, as the cell archives and ThresholdArchive do; it documents this.

Cell archives

QualityDiversity.CellArchive — Type
CellArchive{G,F,D,P}

Supertype of the archives that divide descriptor space into a fixed number of cells and keep the highest-fitness solution found in each: GridArchive, SlidingBoundariesArchive, CVTArchive and CategoricalArchive. They differ in how a descriptor is assigned to a cell and share everything else: storage, add!, add_batch!, sample_elites, elites, length, capacity, empty! and the metrics, including the running totals that make qd_score, max_fitness and mean_fitness constant-time.

A subtype defines cell_index, returning 0 for a descriptor its outside policy rejects, and has these fields, which the shared methods use:

  • outside: an OutsidePolicy
  • occupied::BitVector, fitness::Vector{F}, descriptors::Vector{D}, genotypes::Vector{G}, phenotypes::Vector{P}, occupied_idx::Vector{Int}: one entry per cell
  • fitness_sum::Float64, fitness_sum_error::Float64, fitness_max::F: the running totals described under Metrics in GridArchive
source
QualityDiversity.GridArchive — Type
GridArchive{G,F}(dims, bounds; outside=ThrowOutside(), phenotype=Nothing)
GridArchive{G}(dims, bounds; outside=ThrowOutside(), phenotype=Nothing)
GridArchive(dims, bounds; outside=ThrowOutside(), phenotype=Nothing)
GridArchive(prob::AbstractQDProblem; dims, bounds=descriptor_bounds(prob),
            genotype=Vector{Float64}, fitness=Float64, outside=ThrowOutside(),
            phenotype=Nothing)

Archive that divides descriptor space into a regular grid and keeps the highest-fitness solution found in each cell.

dims is a tuple with the number of cells along each descriptor dimension. bounds is a tuple with one (lo, hi) pair per dimension. G is the genotype type, Vector{Float64} by default, and F<:Real the fitness type, Float64 by default. phenotype is the type of the phenotypes the archive stores, Nothing for none; see Evaluation. The last form takes the bounds from descriptor_bounds(prob) unless bounds is given, for example to zoom in on part of descriptor space.

Descriptors are SVector{N,Float64}. outside says what happens to a descriptor that falls outside the bounds:

  • ThrowOutside() (default): throw an ArgumentError.
  • ClampOutside(): use the nearest cell. A NaN component still throws.
  • RejectOutside(): discard the solution; add! returns a Rejected result.

A solution is stored without copying, so the caller must not modify it afterwards.

Metrics

coverage, qd_score, max_fitness and mean_fitness take constant time: the archive keeps the number of elites, the sum of their fitness and their maximum fitness up to date inside add!, which already knows what changed. A cell is only replaced by a strictly better solution, so the maximum never decreases and a running maximum is exact. The sum changes by new fitness - old fitness for an improved cell and by the fitness for a new cell. It is accumulated in Float64 with compensated (Neumaier) summation, so the rounding error stays within about one rounding of the exact sum however many updates there have been; a plain running sum drifts by hundreds of units in the last place after millions of updates. The value agrees with a fresh pass over the elites, which the generic metrics for any AbstractArchive perform, to within that rounding.

Example

julia> using QualityDiversity

julia> archive = GridArchive((10, 10), ((0, 1), (0, 1)));

julia> length(archive), QualityDiversity.capacity(archive)
(0, 100)

QualityDiversity.SlidingBoundariesArchive — Type
SlidingBoundariesArchive{G,F}(dims, bounds; remap_frequency=100, buffer_capacity=1000,
                              outside=ClampOutside(), phenotype=Nothing)
SlidingBoundariesArchive{G}(dims, bounds; kwargs...)
SlidingBoundariesArchive(dims, bounds; kwargs...)
SlidingBoundariesArchive(prob::AbstractQDProblem; dims, bounds=descriptor_bounds(prob),
                         genotype=Vector{Float64}, fitness=Float64, remap_frequency=100,
                         buffer_capacity=1000, outside=ClampOutside(), phenotype=Nothing)

A grid archive whose cell boundaries follow the distribution of the descriptors found (Fontaine et al., 2019, "Mapping Hearthstone Deck Spaces through MAP-Elites with Sliding Boundaries"). Where descriptors bunch up, the cells are narrow; where they are rare, the cells are wide.

dims, bounds, G, F and phenotype are those of GridArchive, and the archive starts as a regular grid over bounds. It keeps the genotype, fitness, descriptor and phenotype of the last buffer_capacity solutions offered to it, accepted or not. Every remap_frequency solutions it remaps: along each dimension with n cells, boundary j (for j in 1:n) moves to the ⌊(j-1)·m/n⌋+1-th smallest of the m buffered descriptor values and the upper boundary to the largest, so each cell holds about as many buffered descriptors as the next. It then empties the cells and adds back, one at a time, the old elites and the buffered solutions from oldest to newest, so the best solution found is never lost. A cell can have zero width when several buffered descriptors share a value; it stays empty.

A descriptor in cell j along a dimension lies between boundaries j and j+1; a value on a boundary belongs to the cell above it, and a value on the upper boundary to the last cell. A descriptor outside the boundaries is handled by outside, as for a GridArchive, but the default is ClampOutside(): after a remap the outer boundaries are the extremes of the buffer, so new solutions often land outside them. Old elites are always clamped during a remap. Since every offered solution enters the buffer, the boundaries grow toward descriptors outside them. A descriptor with a non-finite component throws an ArgumentError whatever the policy.

add_batch! computes every result against the archive as it was before the batch, as for the other CellArchives. If the number of offered solutions passes a multiple of remap_frequency during the batch, the archive remaps once, after it. ThresholdArchive and SpreadArchive cannot wrap this archive, since their thresholds and spreads belong to cells that move.

The current boundaries are returned by boundaries(archive) and their extremes by descriptor_bounds(archive). empty! also clears the buffer and restores the regular grid over bounds.

Example

julia> using QualityDiversity

julia> archive = SlidingBoundariesArchive((10, 10), ((0, 1), (0, 1)); remap_frequency=50);

julia> length(archive), QualityDiversity.capacity(archive)
(0, 100)

QualityDiversity.CVTArchive — Type
CVTArchive{G,F}(centroids, bounds; outside=ThrowOutside(), phenotype=Nothing)
CVTArchive{G,F}(rng, cells, bounds; samples=100_000, outside=ThrowOutside(),
                phenotype=Nothing)
CVTArchive{G}(...)
CVTArchive(...)
CVTArchive(rng, prob::AbstractQDProblem; cells, bounds=descriptor_bounds(prob),
           samples=100_000, genotype=Vector{Float64}, fitness=Float64,
           outside=ThrowOutside(), phenotype=Nothing)

Archive that divides descriptor space into the Voronoi cells of a set of centroids and keeps the highest-fitness solution found in each cell. A descriptor belongs to the cell of its nearest centroid. Compared with GridArchive, the number of cells does not grow exponentially with the number of descriptor dimensions, and the cells adapt to a measure: with centroids from k-means, a region that the descriptors cover densely gets small cells.

The centroids are either given, as a vector of descriptor-sized vectors, or chosen from samples points drawn uniformly from the box bounds by k-means (Lloyd's algorithm, seeded with k-means++), which makes the cells equal in expected population. The iterations stop after max_iterations (100) or when one lowers the total squared distance from the samples to their centroids by less than 0.1%. The second form draws random numbers, so it takes an rng first; the same seed gives the same centroids. centroids(archive) returns them, and passing them back rebuilds the same archive.

bounds is a tuple with one (lo, hi) pair per descriptor dimension. Given centroids must lie inside the box and be distinct. G is the genotype type, Vector{Float64} by default, and F<:Real the fitness type, Float64 by default. outside says what happens to a descriptor outside the box, as for GridArchive: ThrowOutside(), ClampOutside() or RejectOutside(). phenotype is the type of the phenotypes the archive stores, Nothing for none.

The nearest centroid is found with a k-d tree, so a lookup takes a logarithmic number of distance evaluations in few dimensions and does not allocate. In many dimensions a k-d tree prunes little, and a lookup approaches a pass over all centroids.

The archive keeps the same running totals as GridArchive, so the metrics take constant time.

Example

julia> using QualityDiversity, Random

julia> archive = CVTArchive(Xoshiro(1), 50, ((0, 1), (0, 1)); samples=5_000);

julia> length(archive), QualityDiversity.capacity(archive)
(0, 50)

centroids(archive::CVTArchive) -> Vector{SVector}

The centroids of the cells, in the order of the cell indices.

QualityDiversity.CategoricalArchive — Type
CategoricalArchive{G,F}(categories; outside=ThrowOutside(), phenotype=Nothing)
CategoricalArchive{G}(categories; outside=ThrowOutside(), phenotype=Nothing)
CategoricalArchive(categories; outside=ThrowOutside(), phenotype=Nothing)
CategoricalArchive(prob::AbstractQDProblem; genotype=Vector{Float64},
                   fitness=Float64, outside=ThrowOutside(), phenotype=Nothing)

Archive with one cell for each combination of discrete descriptor values, and the highest-fitness solution found in each. Use it when a descriptor counts or labels something, such as the number of rings in a molecule or a scaffold class, so that only a few values occur and nothing lies between them.

categories is a tuple with one collection of allowed values per descriptor dimension, for example (0:5, [:alkane, :aromatic, :ring]). A value can be anything that has hash and isequal: a number, a Symbol, a String, a Bool, or a tuple. Each collection must be non-empty and have distinct values, and a number must be finite. The last form takes the categories from descriptor_categories(prob).

A descriptor is a tuple with one value per dimension, such as (3, :ring). The descriptor type of the archive is the tuple of the element types of categories, here Tuple{Int,Symbol}, so the archive is concretely typed. A vector with one entry per dimension, such as the SVector of a problem with numeric categories, is accepted as well. Values compare with isequal, except that -0.0 equals 0, so 2.0 matches the category 2. A stored descriptor holds the category values.

The cells are numbered like those of a GridArchive, with the first dimension varying fastest and the values of each dimension in the order given. G is the genotype type, Vector{Float64} by default, and F<:Real the fitness type, Float64 by default. outside says what happens to a descriptor with a component that is not a category:

  • ThrowOutside() (default): throw an ArgumentError.
  • RejectOutside(): discard the solution; add! returns a Rejected result.

ClampOutside() has no meaning for categories and is an error. phenotype is the type of the phenotypes the archive stores, Nothing for none; see Evaluation.

A category is found with a hash lookup, so a lookup takes constant time and does not allocate however many categories there are. A solution is stored without copying, so the caller must not modify it afterwards. The archive keeps the same running totals as GridArchive, so the metrics take constant time.

Example

julia> using QualityDiversity

julia> archive = CategoricalArchive((0:5, [:alkane, :aromatic, :ring]));

julia> length(archive), QualityDiversity.capacity(archive)
(0, 18)

julia> QualityDiversity.cell_index(archive, (3, :ring))
16

Archives around a cell archive

QualityDiversity.ThresholdArchive — Type
ThresholdArchive(archive::CellArchive; learning_rate=1.0, threshold_min=-Inf, result=<copy>)

Archive for CMA-MAE (Fontaine and Nikolaidis, 2023): a cell archive in which each cell has a fitness threshold that rises slowly as solutions enter the cell, instead of jumping to the best fitness found. archive decides which cell a descriptor belongs to, so any CellArchive works: a GridArchive, a CVTArchive or a CategoricalArchive. It must be empty and have a floating-point fitness type, and the new archive uses it without copying.

A solution with fitness f enters its cell if f is strictly greater than the cell's threshold t, and then replaces the cell's elite. The threshold becomes (1 - learning_rate) * t + learning_rate * f. The improvement of the AddResult is f - t, which is what CMA-ME style emitters rank candidates by; for a rejected solution it is zero or negative. Every threshold starts at threshold_min, and a solution can only enter an empty cell if its fitness exceeds that value. A good threshold_min is the lowest fitness the problem can produce, and learning_rate=0.01 is a usual choice.

The elite of a cell is the solution that last passed the threshold, so its fitness can be lower than the one it replaced when learning_rate < 1: a solution above the threshold but below the elite replaces the elite. The archive therefore does not hold the best solution found in each cell. A second, plain archive does: every solution offered to this archive is offered to it as well, and result_archive returns it. Emitters read this archive, and a run reports the metrics of, and returns, the result archive. The result keyword takes that archive; by default it is an empty copy of the wrapped one, and it is nothing when learning_rate=1 and threshold_min=-Inf, where this archive already holds the best solutions and is its own result. It must be empty and of the same type as the wrapped archive.

learning_rate must lie in [0, 1]. With learning_rate=0 the thresholds never change, and with learning_rate=1 a threshold becomes the fitness of the solution that entered. To keep the behavior of an archive with another number of cells, convert the rate with 1 - (1 - learning_rate)^r, where r is the ratio of the cell counts.

The defaults, learning_rate=1 and threshold_min=-Inf, give the rules of the wrapped archive: an empty cell accepts any solution and reports improvement == f, and the threshold of a cell is the fitness of its elite. That setting needs learning_rate=1, so threshold_min=-Inf with a smaller rate is an error.

add_batch! computes the status and improvement of every solution against the archive as it was before the batch, so a solution does not depend on the others in its batch. Of the solutions that pass the threshold of a cell, the one with the highest fitness (the first, on a tie) becomes the elite. The threshold of a cell that m solutions of the batch passed becomes (1 - learning_rate)^m * t + (1 - (1 - learning_rate)^m) * mean(f), where mean(f) is over those solutions, or the highest of their fitness values if threshold_min is -Inf. For a single solution this is the rule above, which is what add! applies. thresholds returns the thresholds, one per cell.

Cells, sampling, elites, length, capacity, cell_index and the stored phenotypes are those of the wrapped archive, and so are the metrics, which describe the elites of this archive and not the result archive. qd_score and mean_fitness take constant time. max_fitness does too, except directly after the best elite was replaced by a worse solution, when the next call makes a pass over the elites.

Example

julia> using QualityDiversity

julia> archive = ThresholdArchive(GridArchive((10, 10), ((0, 1), (0, 1)));
                                  learning_rate=0.5, threshold_min=0);

julia> length(archive), QualityDiversity.capacity(archive)
(0, 100)

QualityDiversity.SpreadArchive — Type
SpreadArchive(archive::Union{GridArchive,CVTArchive})

Archive for MAP-Elites with low spread (Mace et al., 2023, "Don't bet on luck alone"), the archive of MELS: a cell archive that prefers, among solutions of a noisy problem, those whose evaluations land close together. archive decides which cell a descriptor belongs to; it must be empty, and the new archive uses it without copying.

The archive takes the evaluations of a SampledSpread problem, whose descriptor holds the descriptors of all the evaluations of a solution. From them it finds

  • the cell of the solution: the one its descriptors land in most often, the one visited first on a tie;
  • its spread: the mean distance between two of its descriptors, zero for a single one;
  • its stored descriptor: the mean of its descriptors in that cell, which lies inside the cell.

The fitness is the one of the evaluation, the mean over the evaluations by default. An empty cell takes any solution (NewCell, with improvement equal to the fitness). An occupied cell takes a solution only if its fitness is strictly higher and its spread no larger than those of the elite (Improved, with improvement the fitness gain); otherwise the solution is Rejected, with the fitness gain as improvement if it is negative and zero if the spread was the reason. A solution whose descriptors all fall outside the bounds of a RejectOutside() archive, or whose spread is not finite, is Rejected with zero improvement.

add_batch! computes the status and improvement of every solution against the archive as it was before the batch, and the archive afterwards is the one that adding the solutions one at a time gives. spreads returns the spread of every cell. Cells, sampling, elites, length, capacity, the stored phenotypes and the metrics are those of the wrapped archive, which stay exact because an elite is only replaced by a solution with higher fitness.

A CategoricalArchive cannot be wrapped: its descriptors have no distance.

Example

julia> using QualityDiversity, StaticArrays

julia> archive = SpreadArchive(GridArchive((2, 2), ((0, 1), (0, 1))));

julia> samples = QualityDiversity.DescriptorSamples([SVector(0.1, 0.1), SVector(0.2, 0.1), SVector(0.9, 0.9)]);

julia> QualityDiversity.add!(archive, [0.0], Evaluation(1.0, samples)).status
NewCell::AddStatus = 2

julia> only(QualityDiversity.elites(archive))[2].descriptor
2-element SVector{2, Float64} with indices SOneTo(2):
 0.15000000000000002
 0.1

QualityDiversity.DensityArchive — Type
DensityArchive(rng::AbstractRNG, inner::AbstractArchive; bandwidth, buffer_size=10_000)

The archive of Density Descent Search (Lee et al., 2024, "Density Descent for Diversity Optimization"; pyribs DensityArchive). It estimates how densely the descriptors found so far cover descriptor space, so that emitters can move toward where they are sparse.

Every solution goes to inner, an archive with SVector descriptors such as a GridArchive, which holds the solutions: solve returns it, a run records its metrics, and emitters draw their parents and restarts from it. The descriptors also go to a buffer of buffer_size entries that stays a uniform sample of all the descriptors seen, by reservoir sampling (Li, 1994, Algorithm L) with the generator rng. The archive keeps its own copy of rng, since add! takes no generator; init copies the archive, so a run is reproducible from the seed of rng and the seed of the run.

The density at a descriptor y is the Gaussian kernel density estimate of the buffer,

sum(φ(norm(y - b) / h) for b in buffer) / (length(buffer) * h)

with φ the standard normal density and h = bandwidth, in descriptor units, and zero while the buffer is empty. bandwidth has no default; the paper finds about 5% of the width of descriptor space a good start. A result has the status that inner gives the solution and improvement = -density, so that ImprovementRanker ranks the lowest density first. Every result of a batch is computed against the buffer as it was before the batch.

result_archive returns inner, and length, capacity, cell_index, sample_elites, elites, descriptor_bounds and the metrics are those of inner. empty! empties inner and the buffer. The fitness type must be a floating-point type, for the density. DDS builds the algorithm.

Example

julia> using QualityDiversity, Random

julia> archive = DensityArchive(Xoshiro(1), GridArchive((10, 10), ((0, 1), (0, 1))); bandwidth=0.05);

julia> length(archive), QualityDiversity.capacity(archive)
(0, 100)
source

Archives without cells

QualityDiversity.UnstructuredArchive — Type
UnstructuredArchive{G,F}(ndims; capacity, threshold, phenotype=Nothing)
UnstructuredArchive{G}(ndims; capacity, threshold, phenotype=Nothing)
UnstructuredArchive(ndims; capacity, threshold, phenotype=Nothing)
UnstructuredArchive(prob::AbstractQDProblem; capacity, threshold,
                    genotype=Vector{Float64}, fitness=Float64, phenotype=Nothing)

Archive without a fixed partition of descriptor space. It stores up to capacity solutions, each at its own descriptor, and a solution enters if it is far from the ones already stored (novelty) or better than its nearest neighbour (local competition).

ndims is the number of descriptor dimensions; the last form takes it from length(descriptor_bounds(prob)). G is the genotype type, Vector{Float64} by default, and F<:Real the fitness type, Float64 by default. Descriptors are SVector{ndims,Float64}, and distances are Euclidean in descriptor units, so descriptors on very different scales should be normalized by the problem. threshold is the distance beyond which a descriptor counts as new. phenotype is the type of the phenotypes the archive stores, Nothing for none; see Evaluation.

add! finds the stored solution with the nearest descriptor, at distance r:

  • Nothing is stored, or r > threshold: the solution is novel. It fills a free slot (NewCell, with improvement equal to the fitness). If the archive is full, it replaces the stored solution with the lowest fitness, but only if its fitness is strictly higher (NewCell); otherwise it is Rejected.
  • r <= threshold: the solution competes with its nearest neighbour and replaces it if its fitness is strictly higher (Improved, with improvement the difference), and is Rejected otherwise. The new descriptor replaces the old one, so stored descriptors can end up closer together than threshold.

cell_index is the index of the stored solution with the nearest descriptor, or 0 while the archive is empty. capacity is the number of slots, so coverage is the fraction of them in use. Descriptors must be finite; a NaN or infinite component throws an ArgumentError.

The nearest neighbour is found by a pass over the stored descriptors, so add! and cell_index take time linear in the number of stored solutions, and do not allocate. A solution is stored without copying, so the caller must not modify it afterwards. The archive keeps running totals, as GridArchive does, so qd_score, max_fitness and mean_fitness take constant time. The maximum is exact because a stored solution is only ever replaced by a better one.

Example

julia> using QualityDiversity

julia> archive = UnstructuredArchive(2; capacity=100, threshold=0.1);

julia> length(archive), QualityDiversity.capacity(archive)
(0, 100)

QualityDiversity.DNSArchive — Type
DNSArchive{G,F}(ndims; capacity, k, phenotype=Nothing)
DNSArchive{G}(ndims; capacity, k, phenotype=Nothing)
DNSArchive(ndims; capacity, k, phenotype=Nothing)
DNSArchive(prob::AbstractQDProblem; capacity, k, genotype=Vector{Float64},
           fitness=Float64, phenotype=Nothing)

Archive of Dominated Novelty Search (Bahlous-Boldi, Faldor et al., 2025, "Dominated Novelty Search: Rethinking Local Competition in Quality-Diversity"; pyribs DNSArchive, QDax DominatedNoveltyRepertoire). It keeps a population of at most capacity solutions, with no cells and no bounds on descriptor space.

ndims is the number of descriptor dimensions; the last form takes it from length(descriptor_bounds(prob)). G is the genotype type, Vector{Float64} by default, and F<:AbstractFloat the fitness type, Float64 by default. Descriptors are SVector{ndims,Float64}, and distances are Euclidean in descriptor units, so descriptors on very different scales should be normalized by the problem. phenotype is the type of the phenotypes the archive stores, Nothing for none; see Evaluation.

add_batch! merges the batch into the population and gives every solution its dominated novelty: the mean distance to its k nearest other solutions whose fitness is at least as high (all of them if there are fewer), or Inf if there is none. The capacity solutions with the highest scores survive; on a tie, a solution of the batch goes before a stored one, and a later one before an earlier one. A solution of the batch that survives is NewCell and one that does not is Rejected, and its improvement is its score. Since the population is chosen as a whole, the result of a solution depends on the rest of the batch. A neighbour of equal fitness counts as fitter, as in pyribs and QDax, so solutions on a plateau of fitness still compete on distance; the paper counts strictly fitter neighbours only. add! is a batch of one solution.

cell_index is the index of the stored solution with the nearest descriptor, or 0 while the archive is empty, and capacity the population size, so coverage is the fraction of it in use. Descriptors must be finite; a NaN or infinite component throws an ArgumentError. Scoring takes time quadratic in the population plus the batch and keeps only k distances per solution. max_fitness and mean_fitness can decrease, since a solution can leave the population.

Example

julia> using QualityDiversity

julia> archive = DNSArchive(2; capacity=100, k=3);

julia> length(archive), QualityDiversity.capacity(archive)
(0, 100)

ParetoGridArchive(prob::AbstractQDProblem; dims, reference_point, max_front=50,
                  bounds=descriptor_bounds(prob), genotype=Vector{Float64},
                  outside=ThrowOutside(), duplicates=RejectDuplicates(),
                  full_front=RejectNewcomer(), phenotype=Nothing)

Archive for several objectives, the one of MOME (Pierrot et al., 2022): the cells are those of a GridArchive, and every cell keeps a Pareto front, the solutions of the cell that no other solution of the cell beats in every objective, instead of one elite.

dims is the number of cells along each descriptor dimension and bounds the box that they cover, as for a GridArchive. The fitness of a solution is a vector of M objectives, all maximized, and reference_point, a vector of M numbers, is the corner from which hypervolumes are measured. It should lie below the objective values that matter, since a solution contributes hypervolume only where it is larger than the reference point in every objective. A cell keeps at most max_front solutions. The archive stores its fitness values as SVector{M,Float64}. phenotype is the type of the phenotypes the archive stores, Nothing for none; see Evaluation.

add! puts a solution into the front of its cell unless a solution there is at least as good in every objective and better in one; it removes the solutions that the new one beats in every objective. duplicates decides about a solution whose objectives equal those of a stored one: RejectDuplicates (the default) or KeepDuplicates. full_front decides about a solution that beats none of a full front: RejectNewcomer (the default, as in QDax) rejects it and ReplaceCrowded removes the most crowded of the front and the new solution. The result is NewCell for a cell that was empty and Improved otherwise, and its improvement is the hypervolume that the cell gains, a Float64; a rejected solution has an improvement of zero. The results of add_batch! are those of each solution against the archive as it was before the batch, and the solutions are then added in order.

length(archive) is the number of occupied cells, as for the other archives, and num_solutions the number of solutions. elites iterates over all of them. sample_elites draws an occupied cell uniformly and then a solution of its front uniformly.

Metrics

qd_score is the MOQD score, the sum over the cells of the hypervolume of their fronts; it takes no offset. coverage is the fraction of cells that are occupied, max_hypervolume the largest hypervolume of a cell and global_hypervolume the hypervolume of the Pareto front of all the solutions. max_fitness and mean_fitness are not defined for several objectives.

The hypervolume of a front is recomputed whenever a cell changes. It takes no allocation for two objectives; for more it does allocate.

Example

julia> using QualityDiversity, StaticArrays

julia> archive = ParetoGridArchive{Vector{Float64}}((2, 2), ((0, 1), (0, 1)), [0.0, 0.0]);

julia> QualityDiversity.add!(archive, [0.1], Evaluation(SVector(1.0, 3.0), SVector(0.2, 0.2))).status
NewCell::AddStatus = 2

julia> QualityDiversity.add!(archive, [0.2], Evaluation(SVector(3.0, 1.0), SVector(0.2, 0.2))).improvement
2.0

julia> length(archive), num_solutions(archive), qd_score(archive)
(1, 2, 5.0)

RejectDuplicates()

Reject a solution whose objectives equal those of a solution in the front of its cell, so that a front holds every objective vector once. The default of ParetoGridArchive. The MOME paper and QDax's MOMERepertoire keep both; see KeepDuplicates.

QualityDiversity.KeepDuplicates — Type
KeepDuplicates()

Take a solution whose objectives equal those of a solution in the front of its cell, as the MOME paper and QDax's MOMERepertoire do: only a solution that is at least as good in every objective and better in one keeps it out. Different genotypes with equal objectives then all stay, in slots of the front that add no hypervolume.

QualityDiversity.RejectNewcomer — Type
RejectNewcomer()

Reject the solution, so that a full front changes only when a new solution beats one of its solutions in every objective. The default of ParetoGridArchive, as in QDax's MOMERepertoire; the text of the MOME paper replaces a random solution of the front instead.

source
QualityDiversity.ReplaceCrowded — Type
ReplaceCrowded()

Of the solutions of the front and the new one, remove the one with the smallest crowding distance, so that the front stays spread out, as MOME-PGX does (Janmohamed, Pierrot and Cully, 2023, "Improving the Data Efficiency of Multi-Objective Quality-Diversity through Gradient Assistance and Crowding Exploration").

The crowding distance is that of NSGA-II: for each objective, the gap between the two neighbours of a solution in that objective divided by the range of the objective over these solutions, summed over the objectives. The solutions with the smallest and the largest value of an objective have an infinite distance, so the ends of the front are never removed. An objective in which all of them are equal adds nothing. On a tie the new solution is removed, and otherwise the one stored first among those tied.

When the new solution stays, its result is Improved and its improvement is the change in the hypervolume of the cell, which is negative when the removed solution covered more.
