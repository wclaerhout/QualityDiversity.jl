Problems

A problem scores a solution and describes it. Most users wrap a function with QDProblem or StochasticQDProblem; subtyping AbstractQDProblem is for problems that need their own type, for example to define evaluate_batch.

Interface

QualityDiversity.AbstractQDProblem — Type
AbstractQDProblem

Supertype of quality-diversity problems. A problem says how to score a solution and what a random solution looks like.

Fitness is maximized. A problem that minimizes returns the negated value.

Required methods

  • evaluate(prob, x) → Evaluation
  • random_solution(rng, prob)
  • descriptor_bounds(prob), or descriptor_categories(prob) for a problem whose descriptors take discrete values

Optional methods

  • evaluate_batch(prob, xs)
  • fitness_offset(prob)
source
QualityDiversity.AbstractStochasticQDProblem — Type
AbstractStochasticQDProblem

Supertype of problems whose evaluation is random: scoring the same solution twice can give different fitness or descriptors. It is a subtype of AbstractQDProblem. Instead of evaluate(prob, x), such a problem defines

  • evaluate(rng, prob, x) → Evaluation, which draws all its randomness from rng,

next to the other required methods of AbstractQDProblem.

A run stays reproducible from its seed, whatever the number of threads. Before a batch is evaluated, evaluate_batch(rng, prob, xs) draws one seed per solution from the generator of the run, in the order of the batch, and gives every solution its own Xoshiro generator, so which thread evaluates a solution makes no difference. Deterministic problems do not use the generator of the run.

StochasticQDProblem wraps a function, and Sampled evaluates a stochastic problem several times and returns the average.

source
QualityDiversity.Evaluation — Type
Evaluation(fitness, descriptor)
Evaluation(fitness, descriptor, phenotype)
Evaluation{F,D,P}(fitness, descriptor, phenotype)

The result of evaluating one solution.

fitness is a Real for a single objective or an AbstractVector for several. Fitness is maximized; a problem that minimizes returns the negated value. Archives take only finite fitness values: a problem that wants to mark a solution as infeasible returns a low finite value. descriptor locates the solution in descriptor space and is usually an SVector{N,Float64}.

phenotype is what the problem computed from the genotype and described, when the two differ: the product of a reaction sequence, the shape that a set of assembly rules builds. An archive whose phenotype type is P stores it next to the genotype, and elites returns it, so it need not be computed again. Variation sees only genotypes. Without a phenotype the field is nothing and P is Nothing, which takes no memory in an archive.

Example

julia> using QualityDiversity, StaticArrays

julia> Evaluation(1.0, SVector(0.5, 0.5)).phenotype === nothing
true

julia> Evaluation(1.0, SVector(0.5, 0.5), "CCO").phenotype
"CCO"

QualityDiversity.evaluate_batch — Function
evaluate_batch(prob::AbstractQDProblem, xs) -> Vector{<:Evaluation}
evaluate_batch(rng::AbstractRNG, prob::AbstractQDProblem, xs) -> Vector{<:Evaluation}

Evaluate every solution in xs, returning one Evaluation per solution in the same order. Optional: a problem specializes it to evaluate a batch at once, for example on a GPU or through a call into Python.

The default calls evaluate on each solution in parallel with Threads.@threads, so evaluate must be thread-safe.

To evaluate on a GPU, a problem type defines this method: it copies the batch to the device, runs array operations or a kernel, and copies the fitness and descriptor values back. examples/gpu_evaluation.jl does this for any array type of the GPU packages (CUDA.jl, Metal.jl, AMDGPU.jl, oneAPI.jl). The package itself does not depend on any of them.

The candidates of a DeviceCellArchive are a DeviceBatch, whose solutions are the columns of a device matrix. For them the default runs evaluate(prob, x) in a kernel, one solution per thread (for a QDProblem, its function), and returns an EvaluationBatch on the device. That code must then compile for the device: no allocation, no error message built from values, and no Float64 on a device that lacks it. A problem can instead define evaluate_batch(prob::MyProblem, xs::DeviceBatch) and work on parent(xs).

The method with a generator is the one that step! calls, with the generator of the run. For a deterministic problem it calls evaluate_batch(prob, xs) and leaves the generator untouched. For an AbstractStochasticQDProblem it draws one seed per solution from rng, in the order of the batch, and evaluates solution i with evaluate(Xoshiro(seed_i), prob, xs[i]), so the results do not depend on the number of threads. A stochastic problem can define its own method with a generator, for example to evaluate a batch on a device.

Per-dimension collections of the values a discrete descriptor can take, as a tuple, for example (0:5, [:alkane, :aromatic, :ring]). Gradients

The algorithms of differentiable quality diversity (CMAMEGA, CMAMAEGA, OMGMEGA) need the gradients of the fitness and the descriptor. Loading ForwardDiff.jl computes them for most problems; a problem can also give them itself.

QualityDiversity.evaluate_gradient — Function
evaluate_gradient(prob::AbstractQDProblem, x) -> (Evaluation, jacobian)

The Evaluation of the solution x together with the gradients of its fitness and descriptor, for the algorithms of differentiable quality diversity (CMAMEGA, CMAMAEGA, OMGMEGA). Optional: only those algorithms call it.

x is a real vector of length n and the descriptor has N dimensions. jacobian is an (N + 1) × n matrix whose first row is the gradient of the fitness and whose row j + 1 is the gradient of descriptor component j. The fitness is a single real number.

The default differentiates evaluate(prob, x) with ForwardDiff.jl, which must be loaded (using ForwardDiff). The code of the problem must then compute in the number type of x rather than convert its entries to Float64, since ForwardDiff passes vectors of dual numbers; a QDProblem does, if its function does. A problem defines this method itself to give its gradients in closed form, which is faster, or to compute them with another automatic-differentiation package. Sphere and Rastrigin define it in closed form. Stochastic problems have no gradient.

Example

julia> using QualityDiversity, ForwardDiff

julia> prob = QDProblem(x -> (-sum(abs2, x), (x[1], 2x[2]));
                        init = rng -> randn(rng, 2), bounds = ((-3, 3), (-6, 6)));

julia> ev, jacobian = QualityDiversity.evaluate_gradient(prob, [1.0, 2.0]);

julia> ev.fitness
-5.0

julia> jacobian
3×2 Matrix{Float64}:
 -2.0  -4.0
  1.0   0.0
  0.0   2.0

evaluate_gradient_batch(prob::AbstractQDProblem, xs) -> (evaluations, jacobians)

evaluate_gradient for every solution in xs: a vector of Evaluations and a vector of Jacobian matrices, in the order of xs. Wrappers

QualityDiversity.QDProblem — Type
QDProblem(f; init, bounds)
QDProblem(f; init, categories)

Wrap a plain function as a problem. f(x) returns a (fitness, descriptor) tuple for the solution x, or a (fitness, descriptor, phenotype) tuple for a problem whose phenotype an archive should store; see Evaluation. init(rng) returns one random solution.

With bounds, a tuple with one (lo, hi) pair per descriptor dimension, the descriptor is real-valued and evaluate returns it as an SVector{N,Float64}, or with the number type of its components when that is wider, so that ForwardDiff can differentiate evaluate. With categories, a tuple with one collection of allowed values per dimension, for example (0:5, [:alkane, :aromatic, :ring]), the descriptor is discrete and evaluate returns it as a tuple, which a CategoricalArchive takes as it is.

f is called from several threads at once by the default evaluate_batch, so it must be thread-safe.

Example

julia> using QualityDiversity, Random

julia> prob = QDProblem(x -> (-sum(abs2, x), (x[1], x[2]));
                        init = rng -> randn(rng, 2), bounds = ((-3, 3), (-3, 3)));

julia> ev = QualityDiversity.evaluate(prob, [1.0, 2.0]);

julia> ev.fitness, ev.descriptor
(-5.0, [1.0, 2.0])

julia> labelled = QDProblem(x -> (-sum(abs2, x), (length(x), :ring));
                            init = rng -> randn(rng, 2), categories = (1:3, [:chain, :ring]));

julia> QualityDiversity.evaluate(labelled, [1.0, 2.0]).descriptor
(2, :ring)
source
QualityDiversity.StochasticQDProblem — Type
StochasticQDProblem(f; init, bounds)
StochasticQDProblem(f; init, categories)

Wrap a function of a random number generator and a solution as a stochastic problem. f(rng, x) returns a (fitness, descriptor) or (fitness, descriptor, phenotype) tuple for the solution x and draws every random number from rng. The other arguments are those of QDProblem. See AbstractStochasticQDProblem for how the generators are made, and note that f is called from several threads at once.

Example

julia> using QualityDiversity, Random

julia> prob = StochasticQDProblem((rng, x) -> (-sum(abs2, x) + 0.1 * randn(rng), (x[1], x[2]));
                                  init = rng -> randn(rng, 2), bounds = ((-3, 3), (-3, 3)));

julia> a = QualityDiversity.evaluate(Xoshiro(1), prob, [1.0, 2.0]);

julia> a == QualityDiversity.evaluate(Xoshiro(1), prob, [1.0, 2.0])
true

julia> a.fitness == QualityDiversity.evaluate(Xoshiro(2), prob, [1.0, 2.0]).fitness
false

QualityDiversity.Sampled — Type
Sampled(prob; num_samples, expectation=Average())

Score every solution of the stochastic problem prob with num_samples evaluations and return the Expectation of their fitness and, for every dimension, of their descriptor. An archive then holds the averages and not the single lucky evaluation that a noisy problem can give a poor solution.

Sampled is itself a stochastic problem; the evaluations of one solution run one after the other with the generator of that solution, so the results are reproducible from the seed of the run. Every evaluation counts against the budget of a run, so num_samples times fewer solutions are scored for the same budget; see evaluations_per_solution. The fitness must be a real number and the descriptor a vector of real numbers. The descriptor bounds and the fitness offset are those of prob.

If prob returns a phenotype, the result has the phenotype that occurs most often among the evaluations, compared with isequal; on a tie, the one that occurs first. The expectation applies to the fitness and the descriptor only. A phenotype type without its own isequal and hash compares by identity, so every evaluation differs and the result has the phenotype of the first.

Example

julia> using QualityDiversity, Random

julia> noisy = StochasticQDProblem((rng, x) -> (-x[1]^2 + randn(rng), (x[1], x[2]));
                                   init = rng -> randn(rng, 2), bounds = ((-3, 3), (-3, 3)));

julia> prob = Sampled(noisy; num_samples=100);

julia> ev = QualityDiversity.evaluate(Xoshiro(1), prob, [1.0, 0.5]);

julia> abs(ev.fitness + 1) < 0.5
true

julia> QualityDiversity.evaluations_per_solution(prob)
100
source
QualityDiversity.SampledSpread — Type
SampledSpread(prob; num_samples, expectation=Average())

Score every solution of the stochastic problem prob with num_samples evaluations, as Sampled does, but keep every descriptor: the evaluation has the Expectation of the fitness, the descriptors of all the evaluations as a DescriptorSamples, and the phenotype that occurs most often. A SpreadArchive, the archive of MELS, takes these evaluations, and only it: the cell of a solution and its spread depend on the cells of the archive.

The evaluations of one solution run one after the other with the generator of that solution, and each counts against the budget of a run. The fitness must be a real number and the descriptor a vector of real numbers. The descriptor bounds and the fitness offset are those of prob.

Example

julia> using QualityDiversity, Random

julia> noisy = StochasticQDProblem((rng, x) -> (-x[1]^2 + randn(rng), (x[1], x[2] + 0.1 * randn(rng)));
                                   init = rng -> randn(rng, 2), bounds = ((-3, 3), (-3, 3)));

julia> ev = QualityDiversity.evaluate(Xoshiro(1), SampledSpread(noisy; num_samples=5), [1.0, 0.5]);

julia> length(ev.descriptor), ev.descriptor[1][1]
(5, 1.0)

Benchmarks

QualityDiversity.Rastrigin — Type
Rastrigin(dim)

The Rastrigin function as a quality-diversity benchmark over dim real parameters, dim ≥ 2.

The solution is clipped to [-5.12, 5.12] before it is scored. Fitness is the negated Rastrigin value, so the maximum is 0 at the origin. The descriptor is the mean of the first dim ÷ 2 clipped parameters and the mean of the remaining ones, which both lie in [-5.12, 5.12].

Solutions are Vector{Float64}, drawn uniformly from the clipping box.

source
QualityDiversity.Sphere — Type
Sphere(dim)

The sphere with a linear projection of Fontaine et al. (2020), a quality-diversity benchmark over dim real parameters, dim ≥ 2. Its objective is the negated sphere function centered at 0.4 * 5.12 in every parameter, scaled so that the optimum has fitness 100 and the corner -5.12 of the box has fitness 0; a solution farther away has a negative fitness.

The descriptor is the sum of the first dim ÷ 2 parameters and the sum of the rest, after each parameter outside [-5.12, 5.12] is replaced by 5.12 / θ. Because that sum projects many parameters onto one number, most of the solutions land near the center of the descriptor space, and reaching its edges takes solutions that are all at the same end of the box. The descriptor lies in [-5.12 * dim/2, 5.12 * dim/2] in both dimensions.

Solutions are Vector{Float64}, drawn uniformly from [-5.12, 5.12].

source
QualityDiversity.BiSphere — Type
BiSphere(dim)

A benchmark with two objectives over dim real parameters, dim ≥ 2: the negated squared distances to the two points (1, …, 1) and (-1, …, -1). No solution is best in both; the solutions that trade them off best lie on the line between the two points.

The solution is clipped to [-5.12, 5.12] before it is scored. The fitness is an SVector{2,Float64} of the two objectives, which are at most 0. The descriptor is that of Rastrigin: the mean of the first dim ÷ 2 clipped parameters and the mean of the remaining ones. reference_point is the lowest value of both objectives, so every solution adds hypervolume.

Solutions are Vector{Float64}, drawn uniformly from the clipping box.
