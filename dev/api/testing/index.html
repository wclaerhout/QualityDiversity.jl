Testing

QualityDiversity.Testing checks that a new problem, archive, variation or emitter meets its contract. It depends only on the Test standard library, so a package that defines such a type can call it from its own tests; see Extending the package.

QualityDiversity.Testing — Module
QualityDiversity.Testing

Conformance checks for the types a user defines. Each function runs inside a @testset, so failures are reported by the test runner of the caller:

using Test, QualityDiversity
@testset "MyProblem" begin
    QualityDiversity.Testing.test_problem(MyProblem())
end

The checks cover the contract of each role, whether the calls are inferrable, that the results have the right types, and, for archives, that cell_index (and add! for isbits genotypes) does not allocate.

QualityDiversity.Testing.test_problem — Function
test_problem(prob; rng=Xoshiro(1), n=5, rtol=0)

Check that prob meets the contract of AbstractQDProblem, or of AbstractStochasticQDProblem.

random_solution is called n times. Every solution must evaluate to an Evaluation with a real or vector fitness and a descriptor that lies inside descriptor_bounds(prob) and has one entry per bound. For a problem that defines descriptor_categories(prob) instead, the descriptor must be a tuple with one entry equal to a category of each dimension. evaluate must be inferrable, deterministic, and agree with evaluate_batch.

evaluate_batch must give exactly the results of evaluate unless rtol is positive. A problem that evaluates batches on a GPU, in lower precision, agrees only up to rounding: with rtol the fitness and descriptor values then have to match within the relative tolerance rtol, and within rtol in absolute terms for values near zero.

For a stochastic problem, evaluate(rng, prob, x) must give the same result for the same seed, evaluate(prob, x) without a generator must throw, and evaluate_batch(rng, prob, xs) must be reproducible from the generator. rtol does not apply.

QualityDiversity.Testing.test_archive — Function
test_archive(make_archive, prob; rng=Xoshiro(1), n=200, check_allocations=true, elitist=true,
             sequential_batch=true, population=false, gain=true)

Check that the archives built by make_archive() meet the contract of AbstractArchive. make_archive is called without arguments and must return a new, empty archive each time. prob supplies solutions and evaluations; its descriptors must lie inside the archive's bounds. A stochastic problem is evaluated with a fixed seed.

The checks cover an empty archive, the status and improvement of each kind of insertion, length, capacity, cell_index (on an archive holding all n solutions), sample_elites, elites, add_batch!, and empty! when the archive defines it. elites must return the phenotype that came with each stored genotype, of the archive's phenotype type. A fitness that is NaN or infinite must throw an ArgumentError from add! and from add_batch! before the archive changes. With check_allocations, cell_index must not allocate, and neither must add! when the genotype type is isbits.

An archive is elitist if a cell only accepts a solution with higher fitness than its occupant, so that adding the same solution again, or a worse one, is Rejected. An archive whose cells accept solutions below the occupant, such as a ThresholdArchive with a finite threshold_min and a learning_rate below 1, passes elitist=false. The checks then require only that a status agrees with the sign of improvement: Rejected for zero or less, Improved for more than zero.

By default add_batch! must give the results of add! on each solution in order. An archive that computes the results of a batch against its state before the batch, such as a GridArchive or a ThresholdArchive, passes sequential_batch=false. The checks then require that the results are valid and that the result of each solution equals that of adding the solution alone to the archive as it was before the batch.

An archive that chooses its whole population again from the stored solutions and the batch, such as a DNSArchive, passes population=true. A solution then has no cell to improve, so the checks require only that each result is NewCell or Rejected, that the solutions of a batch added to an empty archive that are NewCell are the ones it stores, and that the archive never holds more than its capacity.

By default improvement is a gain in fitness: positive for an Improved solution and zero or less for a Rejected one. An archive that reports another quantity there, such as a DensityArchive, whose improvement is the negated density, passes gain=false, and the checks ignore the value of improvement.

QualityDiversity.Testing.test_front_archive — Function
test_front_archive(make_archive, prob; rng=Xoshiro(1), n=200, check_allocations=true)

Check that the archives built by make_archive() meet the contract of an archive that keeps a Pareto front in every cell, such as a ParetoGridArchive. prob is a problem with a vector fitness whose solutions are evaluated for the checks, and make_archive() returns an empty archive for it whose reference point lies below the fitness values of prob. The fitness type of the archive must be a vector of reals.

The result of add! must be NewCell for an empty cell, Rejected with zero improvement for a solution that a stored one matches in every objective, and Improved with a positive improvement for a solution that beats the front. Every cell must hold a front of solutions none of which beats another, length counts the occupied cells and num_solutions the solutions that elites yields. add_batch! must give each solution the result that it has alone against the archive as it was before the batch, and leave the archive as adding the solutions one at a time does. An objective that is NaN or infinite must throw an ArgumentError from add! and from add_batch! before the archive changes. sample_elites must draw stored genotypes, inferrably, and reproducibly from the generator. elites must return the phenotype that came with each stored genotype. The metrics must agree with the hypervolume of the fronts. add! must not allocate for a rejected solution with an isbits genotype and two objectives when check_allocations is true.

QualityDiversity.Testing.test_variation — Function
test_variation(op, parent; parent2=nothing, rng=Xoshiro(1))

Check that the variation operator op meets the contract of AbstractVariation for the genotype parent. Without parent2 the operator is a mutation, vary(rng, op, parent), and n_parents(op) must be 1; with it, a crossover, vary(rng, op, parent, parent2), and n_parents(op) must be 2.

The call must be inferrable, leave its parents unchanged, and give the same child for the same RNG state. A new child must not be the parent object.

QualityDiversity.Testing.test_emitter — Function
test_emitter(emitter, archive, prob; rng=Xoshiro(1))

Check that emitter meets the contract of AbstractEmitter. archive must be an archive for prob that already holds at least one solution. The check modifies both emitter and archive.

batch_size must be a positive integer, and ask must return that many genotypes of the archive's genotype type, inferrably, as a Vector, or as a DeviceBatch for a DeviceCellArchive, none of them an object the archive stores. The batch must then pass through evaluate_batch, add_batch! and tell!.

An emitter whose ask_gradients returns solutions first gets them back through evaluate_gradient_batch, add_batch! and tell_gradients!, as in step!. For a GradientArchive every batch is evaluated with its gradients.
